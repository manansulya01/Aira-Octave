# Final Report — AiraOS-Octave Autonomous Engineering & Polish Mission (2026-10-14)

### WHAT FOUND
1. **Security defect (high): shadow stayed world-readable.** `initramfs/usr/bin/aira-user`
   `_commit()` did `chmod MODE tmp` then `cat tmp > target`. Redirection keeps the
   target's mode, so `/etc/shadow` remained 0644 after every write. Host
   `scripts/test-user.sh` correctly failed: `shadow mode 644 (is world-readable)`, 72/1.
2. **Incorrect permission assertion (medium):** `initramfs/sbin/guest-usertest.sh`
   accepted any mode matching `6??|4??|2??|0??` as "not world-readable" — 644
   passes that pattern. Same class of bug the mission flagged.
3. **Total IPC bus outage (critical):** every `aira-ipc` call on fresh images returned
   empty; only early rejects worked. New `audit_log()` in
   `initramfs/sbin/aira-ipc-handle` referenced `$5` under `set -u` while the success
   path passes 4 args → abort before responding. Guest autotest showed ~40 IPC FAILs,
   `aia status via IPC` FAIL, doctor `ipc bus` FAIL, `test-services.sh` FAIL.
4. **Build hygiene:** 6 scripts were 0644, not executable: `build-initramfs.sh`,
   `build-gui.sh`, `check-gui-libs.sh`, `test-full.sh`, `pull-screenshots.sh`,
   `test-user.sh`.
5. **GUI issues:** `aira-welcome` had `airapk` typos, documented Alt+F4 as Editor
   (JWM binds Alt+F4 to close; Editor has no dedicated key), used emoji with no
   console/X font coverage, forced `DISPLAY=:0` (headless tried xmessage), `read`
   could hang on closed stdin, and the tour hardcoded `NET: 10.0.2.15` /
   `DSK: 2.1G` invented values. `aira-help` listed only 5 of 11 IPC services,
   had stale Alt+F4 text, `grep -i "$TOPIC"` option-injection on leading-dash
   topics, no `--help`, and failed on hosts where `/usr/share/aira` is unwritable.
   `aira-about` trusted `df /persist` even when unmounted.

### WHAT CHANGED
- `initramfs/usr/bin/aira-user`: `_commit()` now `cat tmp > target` then
  `chmod MODE target`. Minimal, preserves atomic-write design.
- `initramfs/sbin/guest-usertest.sh`: shadow check now validates the others bit
  (`8#MODE & 0004 == 0`); 640/600 pass, 644 correctly fails.
- `initramfs/sbin/aira-ipc-handle`: `audit_log()` uses `${5:-}`; audit logging
  can never abort a request again.
- `scripts/*.sh`: `chmod +x` the 6 non-executable scripts.
- `gui/aira-welcome`: ASCII markers, typo fixes, accurate JWM keys, no forced
  DISPLAY, tty-guarded read, live-or-generic NET/DSK in tour.
- `gui/aira-help`: accurate keys + full 11-service IPC list, `-h/--help`,
  `grep -- "$TOPIC"`, `AIRA_HELP_DIR`/TMPDIR fallback.
- `gui/aira-about`: storage line gated on `/persist` mount.
- Rebuilt `initramfs.cpio` after each meaningful change; regenerated
  `release/MANIFEST.txt` (0 missing).
- Added `reports/baseline-20261013-0925.md`, `docs/DEVELOPMENT_LOG.md`.
- Preserved untouched: pre-existing user rewrites (`init` usertest block,
  `guest-autotest.sh`, `test-all.sh`, `build-initramfs.sh` sync logic),
  unknown artifact `"$_gtmp"|` (left in place), all staged/untracked work.

### WHY
- `_commit`: POSIX redirection does not transfer the temp file's mode bits; only
  chmodding the destination enforces 640 regardless of umask or prior mode.
- Guest shadow regex: Unix permission safety is the others digit, not the owner
  digit; first-digit heuristics accept 644/646/444 as safe.
- `audit_log`: under `set -u`, expanding an unset `$5` is fatal; the 4-arg call
  site killed every successful dispatch while 5-arg early rejects survived —
  exactly the observed failure signature.
- GUI: the runtime is JWM + xmessage + serial console; emoji and invented values
  break that runtime, and docs must match `aira-jwmrc` key bindings. No window
  manager was invented.
